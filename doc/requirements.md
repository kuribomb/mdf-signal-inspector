## 1. プロジェクト概要

### 1.1 目的

MDF4（Measurement Data Format v4）ファイルを読み込み、正規表現で指定した信号が**固着**（値が変化しない）していないかを自動検出・一覧化するデスクトップGUIツールを提供する。

### 1.2 背景

車載ECU開発において、センサー信号やアクチュエーター出力の固着（スタック）は重大な不具合の兆候である。HILテストや実車評価で収録されたMDFログを解析し、固着信号を素早く発見することで、デバッグ・検証作業を効率化する。

### 1.3 スコープ

**v1 に含むもの:**

- MDF4ファイルの読み込み
- 正規表現による対象信号の絞り込み
- 固着判定と結果の一覧表示
- 結果のCSVエクスポート

**v1 に含まないもの（将来フェーズ）:**

- 閾値・期待値によるバリデーション
- TX/RX信号ペアの伝達検証
- 時系列グラフ可視化
- リアルタイム計測への接続
- MDF3対応

## 3. 機能要件

### 3.1 MDF4ファイルの読み込み

| ID | 要件 |
|---|---|
| FR-001 | ファイルダイアログ（または起動引数）でMDF4ファイルを選択・読み込みできること |
| FR-002 | 読み込み完了後、ファイル情報（ファイル名・記録時間・総信号数）をUI上部に表示すること |
| FR-003 | 読み込み中はプログレスインジケータを表示し、UIがフリーズしないこと（非同期処理） |
| FR-004 | ファイルが無効・破損している場合はエラーメッセージを表示し、クラッシュしないこと |

### 3.2 信号フィルタリング

| ID | 要件 |
|---|---|
| FR-010 | 正規表現テキストボックスに入力した式で信号名を絞り込めること |
| FR-011 | 正規表現の文法エラーが発生した場合、テキストボックスをエラー色でハイライトし、エラー内容を表示すること |
| FR-012 | フィルタを空欄にした場合は全信号を対象とすること |

### 3.3 固着検出（コア機能）

| ID | 要件 |
|---|---|
| FR-020 | フィルタリング後の信号に対して「固着チェック実行」操作で固着判定を実行できること |
| FR-021 | **固着の定義:** 計測期間全体を通じてサンプル値の最大値と最小値が等しい（`min == max`） |
| FR-022 | サンプル数が0（空の信号）の場合は判定不能（`N/A`）として扱うこと |
| FR-023 | 結果を以下のカラムで一覧テーブルに表示すること: |

**結果テーブルのカラム定義:**

| カラム名 | 内容 |
|---|---|
| 信号名 | MDFファイル内の信号名 |
| 判定 | `OK`（正常）/ `FAIL`（固着）/ `N/A`（データなし） |
| 固着値 | FAIL時のみ固着している値を表示（OK・N/Aは `-`） |
| サンプル数 | 当該信号のサンプル総数 |

### 3.4 CSVエクスポート

| ID | 要件 |
|---|---|
| FR-030 | 「CSV保存」操作で結果テーブルをCSVファイルとして出力できること |
| FR-031 | CSVのカラム: `signal_name,result,stuck_value,sample_count` |
| FR-032 | 保存先はファイルダイアログで指定できること |

## 4. 非機能要件

### 4.1 アーキテクチャ

GUI と ロジックを明確に分離する。将来のWeb公開（FastAPI等）に備え、コアロジックはGUIフレームワークに依存しない純粋なPythonとする。

```
src/
└── mdf_signal_inspector/
    ├── core/               # GUIに非依存。将来 api/ からも呼び出せる
    │   ├── mdf_loader.py   # MDF4読み込み・信号メタデータ抽出
    │   └── stuck_detector.py  # 固着判定ロジック
    └── ui/                 # PySide6 View層。core を呼び出すだけ
        └── main_window.py
```

**原則:**
- `core/` は `PySide6` を import しない
- `ui/` はビジネスロジックを持たない（coreへの委譲のみ）
- `core/` はCLIスクリプトからも単独で呼び出し可能

### 4.2 パフォーマンス

| 指標 | 目標値 |
|---|---|
| ファイル読み込み時間 | 1GB以下のMDF4を60秒以内 |
| フィルタ反映 | 入力から500ms以内に結果を反映 |
| 固着判定実行 | 1,000信号・各10万サンプルを30秒以内 |

### 4.3 信頼性

- `core/stuck_detector.py` の固着判定ロジックはpytestで単体テスト必須
- 空データ・NaN値を含む信号に対してクラッシュしないこと

### 4.4 動作環境

| 項目 | 要件 |
|---|---|
| OS | Windows 10/11、macOS 13以降、Ubuntu 22.04以降 |
| Python | 3.11以降 |
| MDF形式 | MDF4（`.mf4`） |

## 6. 画面構成

### 6.1 メインウィンドウ レイアウト

```
+--------------------------------------------------+
|  MDF Signal Inspector                  [_][□][×] |
+--------------------------------------------------+
|  [ファイルを開く]  ファイル名: sample.mf4          |
|  記録時間: 60.0 s   信号数: 1240                  |
+--------------------------------------------------+
|  信号フィルタ（正規表現）:  [              ]       |
|                                                  |
|  [固着チェック実行]              [CSV保存]         |
+--------------------------------------------------+
|  信号名                  | 判定 | 固着値 | サンプル数 |
|  ECU1_Speed              | OK   |   -   |   6000   |
|  ECU1_Throttle           | FAIL |  0.0  |   6000   |
|  ECU1_BrakePress         | OK   |   -   |   6000   |
|  ECU2_EngineTemp         | N/A  |   -   |      0   |
+--------------------------------------------------+
|  [ステータスバー: 読み込み完了 / 実行中... / エラー] |
+--------------------------------------------------+
```

### 6.2 UI要素の説明

| 要素 | 説明 |
|---|---|
| ファイルを開くボタン | `QFileDialog` でMDF4ファイルを選択 |
| ファイル情報ラベル | ファイル名・記録時間・信号数を表示 |
| 正規表現テキストボックス | `QLineEdit`。エラー時は背景を赤くハイライト |
| 固着チェック実行ボタン | フィルタ済み信号に対して固着判定を実行 |
| CSV保存ボタン | 結果テーブルをCSV出力 |
| 結果テーブル | `QTableView` + `QAbstractTableModel` |
| ステータスバー | `QStatusBar`。処理状況・エラーを表示 |
